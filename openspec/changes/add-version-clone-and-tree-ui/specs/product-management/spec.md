# Spec Delta

## ADDED Requirements

### Requirement: 复制为新版本
系统管理员 SHALL 能把一个已有的版本复制成一个新版本。复制 SHALL 在一个事务里完成。新版本属于同一个产品线，名称必须唯一，状态为未上线，并记录来源版本。

#### Scenario: 复制成功
- **WHEN** 系统管理员把版本 2.0.0 复制为 3.0.0
- **THEN** 产品线下出现一个名为 3.0.0 的未上线版本，来源是 2.0.0

#### Scenario: 名称重复
- **WHEN** 系统管理员把版本复制为该产品线下已经存在的名称
- **THEN** 返回 409，不创建任何数据

#### Scenario: 编辑复制版本
- **WHEN** 角色为编辑的用户请求复制版本
- **THEN** 返回 403

### Requirement: 复制的内容
复制出的新版本 SHALL 在结构、内容和发布状态上与来源版本一致，并且此后与来源版本互不影响。

#### Scenario: 结构一致
- **WHEN** 来源版本里有多层分类，每个分类下有文档
- **THEN** 新版本的目录树与来源版本逐层一致，顺序相同

#### Scenario: 内容与发布状态一致
- **WHEN** 来源版本里的语言版本有的已发布，有的只有草稿
- **THEN** 新版本里对应的语言版本内容相同，已发布的仍然是已发布，线上内容也相同

#### Scenario: 新版本与来源互相独立
- **WHEN** 复制完成之后，成员在新版本里修改并发布一篇文档
- **THEN** 来源版本里这篇文档的内容不变

#### Scenario: 译文过期状态一致
- **WHEN** 来源版本里某篇译文被标记为过期，另一篇没有
- **THEN** 新版本里对应的译文也被标记为过期，另一篇没有

#### Scenario: 复制来的草稿不算未发布修改
- **WHEN** 复制刚完成时查看新版本
- **THEN** 没有任何语言版本被标记为“有未发布修改”

#### Scenario: 只带入线上的修订
- **WHEN** 来源版本里某篇文档发布过多次
- **THEN** 新版本里这篇文档的历史只有一条来源为“复制”的修订

#### Scenario: 复制中途失败
- **WHEN** 复制过程中某一步失败
- **THEN** 不留下新版本，也不留下任何分类、文档或修订

### Requirement: 版本列表统计
版本列表的每一项 SHALL 带上该版本的文档数，以及“有未发布修改”的语言版本数。

#### Scenario: 上线前查看统计
- **WHEN** 系统管理员查看版本列表，其中版本 V 有 20 篇文档、3 个语言版本改了但没有发布
- **THEN** V 这一项显示文档数 20、未发布修改数 3
