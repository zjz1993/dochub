## 1. 修订

- [ ] 1.1 **修订表设计**（1h｜你设计｜前置：任务 1.1（`add-language-versions-and-drafts`））：自己设计 `revision`，对照 `docs/database-conventions.md` 的表设计，写 `V6`。 验证：你能解释回滚为什么不删除新修订。

## 2. 发布

- [ ] 2.1 **发布与下线**（3h｜你写（重点）｜前置：任务 1.1、任务 1.3（`add-edit-lock-and-editor`））：发布：校验持锁，在一个事务里插入修订、更新指针、发布时间、发布人。下线：指针置空，历史保留。把任务 1.3（`add-edit-lock-and-editor`）留的发布校验点接上。补上任务 3.1（`add-category-tree-and-documents`）留的 TODO：没有任何已发布的语言版本才允许删除文档，否则返回 409。 验证：发布后多一条修订且指针指向它；人为让事务的第二步失败，修订不残留；下线后修订仍在；删除已发布的文档返回 409。 测试：4 条集成测试（发布、事务失败回滚、下线、删除已发布文档被拒）
- [ ] 2.2 **修订历史与回滚**（2.5h｜你写｜前置：任务 2.1）：历史列表（分页）、查看一条修订。回滚：新建一条回滚修订，让线上指向它，立即生效。回滚不改草稿。 验证：回滚后线上是旧内容；历史里多一条回滚记录。 测试：2 条集成测试
- [ ] 2.3 **译文过期标记**（1.5h｜你写｜前置：任务 2.1）：发布译文时记下原文当时的线上修订；过期判断写成纯函数；列表接口返回 `outdated`。 验证：原文重新发布后，译文标记为过期；译文重新发布后，标记消失。 测试：3 条单元测试、1 条集成测试

## 3. 发布与历史页面

- [ ] 3.1 **发布与修订历史页**（2h｜AI 写，你联调｜前置：任务 2.2、任务 2.3）：编辑器页加“发布”“下线”按钮和当前状态；修订历史页（列表、查看、回滚）；语言版本列表上的“原文已更新”标记。 验证：在页面上发布一篇文档后，历史里出现这条修订；回滚后页面内容变为旧内容；原文重新发布后，译文的过期标记出现。
