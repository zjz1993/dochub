## 1. 编辑锁

- [ ] 1.1 **编辑锁设计**（1h｜你在纸上设计｜前置：无，可提前）：写清楚 Redis 的键名和值、过期时间、心跳间隔、空闲阈值；获取、续期、释放各用哪条命令；什么情况下返回冲突；哪些接口要校验持锁。 验证：设计经审查通过后再写代码。
  - 参考取值：键 `dochub:lock:lv:{语言版本id}`，值是令牌（用户 id 加随机串）；过期 300 秒；编辑器每 60 秒心跳一次，只在最近 5 分钟内有操作时才发。
- [ ] 1.2 **上锁、续期、释放**（3.5h｜你写（重点）｜前置：任务 1.1）：`EditLockService`。获取用 `SET NX EX`；续期和释放各写一段 Lua，值等于自己的令牌才操作；获取失败时返回持有者和开始时间。 验证：两个人同时获取只有一个成功；非持有者续期、释放都无效；锁到期后能被他人获取。 测试：4 条集成测试，用 Redis 容器
- [ ] 1.3 **保存与发布的持锁校验**（1.5h｜你写｜前置：任务 1.2、任务 2.1（`add-language-versions-and-drafts`））：保存草稿时校验请求头里的锁令牌，不是当前持锁人返回 409 并带持有者信息；给发布接口留好同样的校验点，第 7 周接上；在代码注释里写明“查锁和写库之间的空档”。 验证：未持锁保存返回 409；持锁人保存成功。 测试：2 条集成测试
- [ ] 1.4 **空闲过期与“继续编辑”**（1.5h｜AI 写前端，你写测试｜前置：任务 1.2）：前端检测到 5 分钟无操作后停止心跳并转只读，点“继续编辑”重新上锁，离开页面时释放。后端用较短的过期时间写一条“到期后可被他人获取”的测试。 验证：关闭页面后最多 5 分钟，别人可以编辑。 测试：1 条集成测试

## 2. 编辑器页

- [ ] 2.1 **文档编辑器页**（2.5h｜AI 写，你联调｜前置：任务 1.3、任务 1.4）：文档的语言版本列表；编辑器页（Textory、标题、切换语言、自动保存、手动保存、预览切换、图片上传接到后端接口、锁状态提示）。 验证：两个浏览器窗口模拟两个人：后者只能查看，并看得到持有者；前者空闲后自动转只读；粘贴图片能上传并显示。
