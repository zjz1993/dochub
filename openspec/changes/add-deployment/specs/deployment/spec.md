# Spec Delta

## Purpose

规定 DocHub 在生产环境怎么运行：容器化的四个服务、对外的访问入口、初始账号、生产环境的加固、备份与回滚。部署的目标是作者自己的一台资源有限的共享服务器，所以对资源有硬性的限制。

## ADDED Requirements

### Requirement: 容器化运行
生产环境 SHALL 用一份编排文件运行四个服务：MySQL、Redis、后端、前端。数据库的结构由后端在首次启动时通过迁移创建。

#### Scenario: 在服务器上启动全部服务
- **WHEN** 在服务器上用生产编排文件启动
- **THEN** 四个容器都在运行，健康检查通过，站点可以访问

#### Scenario: 在开发机上完整预演
- **WHEN** 在开发机上用同一份生产编排文件启动
- **THEN** 四个容器都在运行，登录、编辑、发布、展示端可见的整条链路可以通过

### Requirement: 资源限制
每个容器 SHALL 设内存上限，四个容器的内存上限合计 MUST 不超过 1.2GB。

#### Scenario: 查看内存占用
- **WHEN** 四个容器启动，并完成一次登录、编辑、发布之后，查看容器的内存
- **THEN** 四个容器的内存合计不超过 1.2GB

### Requirement: 端口暴露最小化
只有前端容器 SHALL 发布到宿主机，并且只绑定 `127.0.0.1:3100`。MySQL 和 Redis MUST NOT 对宿主机或公网开放端口。

#### Scenario: 检查端口
- **WHEN** 服务启动之后查看宿主机上的监听端口
- **THEN** 新增的监听只有 `127.0.0.1:3100`，没有 MySQL 和 Redis 的新监听

### Requirement: 初始系统管理员
以生产配置启动时，如果配置了初始管理员的环境变量，并且系统里还没有系统管理员，系统 SHALL 创建这个账号。没有配置该变量时，MUST NOT 创建任何账号。

#### Scenario: 首次启动
- **WHEN** 以生产配置、带着初始管理员的用户名和密码环境变量，在空数据库上首次启动
- **THEN** 系统里出现一个系统管理员，可以用它登录

#### Scenario: 再次启动
- **WHEN** 之后带着同样的环境变量重启
- **THEN** 不会重复创建账号，已有账号的密码不变

#### Scenario: 没有配置初始管理员
- **WHEN** 以生产配置启动，但没有配置初始管理员
- **THEN** 系统里没有任何账号

### Requirement: 生产环境加固
以生产配置运行时，系统 SHALL 关闭接口文档的界面，让 Cookie 带上 `Secure`，并且全部密钥来自环境变量。

#### Scenario: 访问接口文档
- **WHEN** 在生产环境请求接口文档的地址
- **THEN** 返回 404

#### Scenario: 镜像里没有密钥
- **WHEN** 检查生产镜像里的配置文件
- **THEN** 只有环境变量的引用，没有任何密钥的取值

### Requirement: 反向代理与 HTTPS
服务器上的反向代理 SHALL 把 `/api/` 和 `/files/` 的请求转给后端，其余的请求转给前端，并通过 HTTPS 对外提供站点。服务器上原有的站点 MUST 不受影响。

#### Scenario: 通过 HTTPS 访问
- **WHEN** 浏览器访问站点的首页
- **THEN** 展示端的页面正常显示，证书有效

#### Scenario: 前后端同源
- **WHEN** 浏览器从站点发起登录请求
- **THEN** 请求发往同一个域名下的 `/api/admin/auth/login`，登录的 Cookie 被浏览器保存

#### Scenario: 原有的站点不受影响
- **WHEN** DocHub 启动之后，访问服务器上原有的博客站点
- **THEN** 博客仍然可以正常访问

### Requirement: 部署前预检
部署之前 SHALL 检查服务器的资源：磁盘可用不少于 15GB，可用内存不少于 1.8GB。不满足时 MUST NOT 部署。

#### Scenario: 资源不达标
- **WHEN** 预检发现可用内存只有 1.3GB
- **THEN** 部署暂停，先由作者清理资源

### Requirement: 备份与恢复
系统 SHALL 每天自动备份数据库和上传文件的目录，各保留最近 7 份。备份 MUST 经过至少一次恢复演练。

#### Scenario: 手动触发备份
- **WHEN** 手动执行备份脚本
- **THEN** 生成当天的数据库备份和文件目录备份

#### Scenario: 恢复演练
- **WHEN** 把一份数据库备份恢复到一个空的实例
- **THEN** 之前发布的文档、用户和修订都能查到

### Requirement: 回滚
升级出问题时，系统 SHALL 能通过把镜像切回上一个版本标签来完成回滚。

#### Scenario: 回滚到上一个版本
- **WHEN** 把编排文件里的镜像标签改回上一个版本，并重新启动
- **THEN** 站点恢复为上一个版本的行为，数据仍然可读

### Requirement: 项目说明
仓库的 README SHALL 写明部署、升级和回滚的步骤，以及一份上线后的冒烟清单，照着做能完成一次重新部署。

#### Scenario: 照着文档重新部署
- **WHEN** 按 README 的步骤在一台干净的服务器上操作
- **THEN** 站点被成功部署，并通过冒烟清单
