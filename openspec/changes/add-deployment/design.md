# Design

## Context

动机见 proposal.md。服务器的现状（内存、磁盘、端口、已有的容器和 nginx）见 `docs/development-guide.md` 的“环境与服务器现状”。

## Goals / Non-Goals

**Goals:**
- 站点通过 HTTPS 可以访问。
- 服务器上原有的博客和其他服务不受影响。
- 出问题时能在几分钟之内回到上一个版本。

**Non-Goals:**
- 持续集成、多实例、监控告警、CDN。

## Decisions

1. **镜像在 Mac 上构建，目标平台是 linux/amd64，与服务器一致；用 `docker save` 经 ssh 传输，再在服务器上 `docker load`。** 不在服务器上构建：Maven 构建会吃掉大量内存，而这台机器已经用着 2.5GB 的 swap。也不搭镜像仓库：只有两个镜像、一台服务器。
2. **只有前端容器发布到宿主机，并且只绑定 `127.0.0.1:3100`。** MySQL 和 Redis 只在编排的内部网络里可见。宿主机上已经有 MySQL（3306）、Redis（6379）、一个占用 3000 端口的应用，以及 nginx 的 80 和 443。
3. **每个容器设内存上限，并调小 JVM、MySQL、Next.js 默认的内存占用。** 上限合计控制在 1.2GB 以内，这也是预检门槛（可用内存不少于 1.8GB）的依据。
4. **复用宿主机上由宝塔管理的 nginx。** 为子域名新增一个站点：`/api/` 和 `/files/` 转给后端容器，其余转给前端容器；证书在宝塔里签发。不另起一个反向代理，避免两个 nginx 抢 80 和 443。
5. **预检不达标就不部署。** 门槛是磁盘可用不少于 15GB、可用内存不少于 1.8GB。清理哪些镜像、停哪些服务由作者决定；AI 只列清单，经确认后由作者执行。
6. **初始管理员在首次启动时按环境变量创建，不存在才创建。** 密码不进仓库，也不进镜像；dev 环境的种子账号不会出现在生产。
7. **生产环境关闭接口文档，只开放健康检查；Cookie 加 `Secure`。** Spring Boot 3.5 已经停止开源安全支持（见 `docs/decisions/ADR-005-spring-boot-3-5-over-4.md`），所以公网上只开放展示端和管理端的登录。
8. **备份用独立脚本加 crontab，不放进宝塔面板。** 这台机器上有过面板里的定时任务被丢弃的经历。数据库每天备份一次，保留 7 份，上传的文件目录一起备份；备份要做过一次恢复演练才算数。
9. **回滚是切回上一个镜像标签。** 编排文件里的镜像标签就是版本号，保留最近三个版本。

## Migration Plan

1. 预检：清理资源、添加 DNS 记录、签发证书。
2. 部署：传输镜像、写 `.env`、启动。首次启动时自动执行迁移并创建管理员。
3. 冒烟：登录、编辑、发布、展示端可见。
4. 确认原有的站点不受影响，然后配置备份。

回滚：把编排文件里的镜像标签改回上一版，重新启动。数据库迁移只前进，所以迁移脚本必须与旧版本兼容：只增加表和列，不改变已有列的含义。
