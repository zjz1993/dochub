# Design

## Context

动机见 proposal.md。接口见 `docs/api-conventions.md` 的“语言版本、草稿与编辑锁”“文件”两节，表结构见 `docs/database-conventions.md`。

## Goals / Non-Goals

**Goals:**
- 草稿正文保存到库里的那一刻就是安全的。
- 白名单以编辑器的真实产出为依据，正常的表格、代码块、图片不被误删。
- 存储方式可以替换，业务代码不感知。

**Non-Goals:**
- 编辑锁（第 6 周）。
- 附件（非图片）、视频、MinIO。

## Decisions

1. **净化用 Jsoup 的 `Safelist` 白名单，在 Service 保存前执行；不做黑名单。** 先从编辑器导出每种节点的真实 HTML 存成测试夹具，按夹具确定允许的标签和属性。白名单漏掉的只是显示效果，黑名单漏掉的是安全。
2. **`style` 属性和 svg 默认不放行，除非夹具证明必须。** 带样式的文本（颜色、对齐）如果编辑器用内联样式实现，再逐项放开。
3. **语言版本的唯一键是 `(document_id, locale)`。** 标题存在语言版本上，所以标题天然按语言区分。分类名称同理，另有一张表。
4. **新建语言版本时预填默认语言版本的内容：有已发布内容用已发布，否则用草稿。** 翻译人员在其上改写，图片和表格的结构得以保留。
5. **预填、新建文档并创建默认语言版本，都在 Service 的事务里完成。** 一个请求写两张表。
6. **线上内容不在本变更出现。** `language_version` 表里现在就有指向修订的字段，但一直为空；发布在 `add-document-publishing` 实现。
7. **文件存储定义 `FileStorage` 接口，先做本地磁盘实现。** 文件名用 UUID，按年月分目录，地址形如 `/files/{年月}/{uuid}.{扩展名}`。以后换 MinIO 只换实现。
8. **只允许 png、jpg、jpeg、gif、webp，单张不超过 10MB，拒绝 svg。** svg 可以内嵌脚本。扩展名和实际的文件头都要校验。
9. **`/files/**` 公开可读。** 已发布文档的图片读者本来就能看；草稿图片的地址是随机 UUID，无法枚举。

## Risks / Trade-offs

- [白名单过严，编辑器的某些格式保存后丢失] → 用夹具驱动的测试暴露；发现缺失时先加样本，再加规则。
- [白名单过松] → 每个已知的攻击形态（脚本标签、事件属性、`javascript` 协议）各有一条测试。
- [文件访问接口被用来读任意文件] → 路径解析后必须落在存储根目录内，否则 404；有一条带 `../` 的测试。
- [草稿里的图片公网可达] → 接受：地址不可猜，内容本身是文档配图。
