## 1. 产品线与数据范围

- [ ] 1.1 **产品线接口**（2h｜你写｜前置：任务 4.1（`add-access-control`））：新增（`code` 唯一）、修改、排序、启用停用、列表、详情。不提供删除，用停用代替。 验证：重复 `code` 返回 409；停用的产品线带着状态出现在管理端列表里。 测试：2 条集成测试（重复 code 409；停用后状态正确）
- [ ] 1.2 **数据级鉴权：编辑只看到自己的产品线**（1.5h｜你写（重点）｜前置：任务 1.1）：写 `AccessChecker`：系统管理员直接通过，编辑查成员表；产品线列表对编辑只返回被分配的；详情无权时返回 403。 验证：编辑甲请求产品线 B 的详情返回 403，请求自己的返回 200。 测试：2 条集成测试

## 2. 产品版本

- [ ] 2.1 **产品版本表设计与增改、上线、下线**（2.5h｜你写｜前置：任务 1.1）：设计 `product_version`，对照 `docs/database-conventions.md` 的表设计，写 `V3`。在产品线下新建版本（同一产品线内名称唯一）、改名、排序、上线、下线、删除（只允许删除未上线且没有任何文档的版本）。版本列表先留出“文档数、未发布修改数”两个字段，第 8 周补上计算。 验证：同一产品线下重名版本返回 409；上线后状态和上线时间正确；上线过的版本不能删除。 测试：3 条集成测试（重名 409；上线与下线；删除被拒）
