# Design

## Context

动机见 proposal.md。接口见 `docs/api-conventions.md` 的“展示端”。可见性和回退的规则在 `docs/domain-model.md` 的“派生状态”。

## Goals / Non-Goals

**Goals:**
- 公开的接口没有任何路径能读到草稿或未上线的内容。
- 读者永远有点得开的内容，不会遇到空页面。
- 各语言共用一棵目录树，查询简单。

**Non-Goals:**
- 按语言隐藏没有翻译的文档、全文搜索、登录后访问、服务端渲染的性能优化。

## Decisions

1. **四个接口共用同一个入口校验：产品线已启用，并且版本已上线，否则返回 404。** 展示端不返回 403，因为对匿名读者要隐藏“它存在，只是你看不到”。每个接口都有一条“未上线返回 404”的测试。
2. **目录树各语言共用：只出现至少有一个已发布语言版本的文档，并剪掉空分类。** 一次取回版本下全部已发布的语言版本，在内存里算可见性、组装树、按语言选名称和标题。
3. **回退顺序：所需语言的已发布内容 → 默认语言的已发布内容 → 任意一种已发布的语言 → 404。** 响应里带上请求的语言、实际返回的语言和是否回退，前端据此显示提示。按语言隐藏没有翻译的文档，体验更干净，但树查询要按语言联表过滤，留给以后。
4. **回退是数据级的规则，写成纯函数。** “版本状态 × 语言有无 × 是否发布”的组合至少有六条测试。
5. **展示端只返回读者需要的字段**：标题、净化后的正文、更新时间。修订的 id、锁、内部状态都不出现在响应里。
6. **服务端渲染，地址带三个维度。** `/{产品线code}/v{版本id}/{docKey}?locale=`。`docKey` 跨版本稳定，所以切换版本之后可以停在同一个文档上；目标版本没有这篇文档时，回到目录导航的第一个节点。
7. **展示端渲染前再净化一次正文。** 后端保存时已经净化，这是第二道保险。

## Risks / Trade-offs

- [某个新接口忘了加入口校验] → 展示端的 Controller 只调用 `portal/` 包里的 Service，校验集中在这个包的一个方法里。
- [英文界面上出现中文正文] → 回退提示是约定的一部分；按语言隐藏留作后续。
- [服务端渲染拖慢响应] → MVP 不做缓存；访问量上来之后再考虑。
