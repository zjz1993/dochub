# 文档正文以 HTML 字符串存储

DocHub 用 Tiptap 编辑器（Textory）编辑正文。Tiptap 的原生格式是 JSON，也有不少文档系统用 Markdown。我们决定：草稿和修订里的正文一律存 HTML 字符串，由后端按白名单净化后保存，展示端直接渲染。

## 考虑过的方案

- **Tiptap JSON**：对编辑器无损，但 Java 后端读不懂内容，展示端必须打包编辑器扩展才能把 JSON 转成 HTML；修订对比和全文搜索都只能对着 JSON 做。
- **Markdown**：纯文本最便于对比和检索，但非技术写作者不习惯，表格和截图的体验差，和参考产品的富文本形态不一致；图片上传接口也省不掉。

## 后果

- 后端把正文当成不需要理解内部结构的文本：存储、复制版本、修订、按语言预填都不涉及编辑器的数据结构。
- 保存时必须净化：正文是可直接渲染的 HTML，不净化就发布等于开放存储型 XSS。展示端渲染时再净化一次。
- 编辑器以后如果产生无法用 HTML 表达的节点状态，会丢失；届时再评估是否补存 JSON。
