# 模块化单体：一个后端应用，按业务分包

DocHub 有登录、产品线、版本、分类、文档、发布、展示端等多块业务，数据量小，开发维护只有一个人。我们没有拆微服务，也没有引入消息队列、服务注册等中间件，而是做一个 Spring Boot 单体应用，内部按业务分包（`auth`、`productline`、`productversion`、`category`、`document`、`content`、`publishing`、`portal` 等），包内再分 Controller、Service、Mapper。

## 理由

- 业务之间共享同一个数据库，发布、复制版本这类操作要跨多张表。单体里一个事务就够，拆成服务后要处理分布式事务。
- 一个人、12 周、约 100 小时的预算，运维成本必须接近零。
- 模块边界靠包结构和分层约定维持。将来某一块确实需要独立时，再沿着包边界拆出去。

## 后果

- 包之间只能通过 Service 互调，不能跨包使用对方的 Mapper；跨业务的规则集中在 `access` 和 `common`。
- 新增中间件必须有明确理由，并单独记录一条 ADR。Redis 是第一个，见 ADR-004。
