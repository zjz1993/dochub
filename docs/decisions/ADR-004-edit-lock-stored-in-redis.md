# 编辑并发用编辑锁，锁存 Redis

DocHub 的文档会由多人编辑，同一篇文档也可能被两个人同时打开。这种情况常见的做法是乐观锁：保存时版本号对不上就拒绝。我们决定用编辑锁：一个语言版本同一时刻只允许一个人编辑，别人只能查看；持有者连续 5 分钟没有操作，或者页面关闭、崩溃之后，锁自动失效。锁存在 Redis 里，不存 MySQL。

## 考虑过的方案

- **乐观锁**：实现最省，也不会丢数据；但后保存的人要刷新重做，而且没有任何“别人正在编辑”的提示。
- **编辑锁存 MySQL**：锁和它保护的数据在同一个库，确认持锁和写入草稿可以一步完成，也不用新增服务。Redis 换来的是原生的过期时间，以及心跳不经过 MySQL。

## 后果

- Redis 成为运行和集成测试的必需服务；它不可用时没人能编辑。
- 确认持锁（Redis）和写入草稿（MySQL）是两步，中间有毫秒级的空档：锁刚好过期并被他人取得时，原持有者的写入仍会落库。
- 续期和释放必须先确认锁是自己的。在 Redis 里要保证“比较再操作”的原子性需要 Lua 脚本，否则已经过期的持有者会续上或删掉别人的锁。
- 不做强制接管，需要时再加。
