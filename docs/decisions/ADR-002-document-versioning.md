# 每个产品版本拥有独立的一套文档（整版复制，不做版本间继承）

DocHub 要支持同一产品的多个版本并存，而新版本的大部分文档沿用自上一版，很容易想到让版本之间共享内容。我们决定不做共享：每个产品版本拥有自己完整的一套文档，新建产品版本时从指定的已有版本整版复制（各语言版本的草稿和已发布内容原样保留），此后各版本互不影响。

## 考虑过的方案

- **继承 + 覆盖**：新版本默认沿用上一版内容，只有改过的文档才独立。没有内容冗余，公共修改自动生效；但需要版本排序、读取时的回退链、发布继承规则和“本版本已删除”标记，而且重新发布旧版本会改变新版本对外展示的内容。对 MVP 来说复杂度不成比例。
- **空白版本 + 按需导入**：实现最简单，但编辑要在每个新版本上重复大量搬运工作。

## 后果

- 内容在版本之间冗余，公共内容的修改需要在每个版本各做一次，和同时维护多个 git 分支是同一种代价。
- 文档没有跨版本的稳定身份。将来如果需要跨版本对比或同步，再给文档增加“同源文档”关联。
- 复制来的内容保持“已发布”状态，新版本靠自己的上线状态对读者隐藏。上线由产品版本的开关控制，不做逐篇重新发布，也不做批量发布。改了草稿但忘了发布的文档，上线后读者看到的是旧内容。
